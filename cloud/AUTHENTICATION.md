# 云端认证与账号数据边界

本文说明当前源码中的认证设计，不是独立安全审计。云端和本机是两套独立账号、密钥与聊天数据；任何账号迁移都必须另行设计。

## 密码派生与身份

新密码在客户端先做 Unicode NFC 规范化，长度按 Unicode 码点计为 1–12。此限制只用于注册、改密和恢复设新密码；服务端登录路径不限制旧密码长度，以兼容既有较长密码。短密码极易被猜测。

`src/crypto.mjs` 将规范化密码以 PBKDF2-HMAC-SHA256 派生 256 位主密钥，使用每账号 16 字节随机 salt 和 600,000 次迭代；随后以 HKDF-SHA256 和不同固定上下文标签导出 `authKey` 与 vault 加密密钥。客户端提交派生的 `authKey`，不提交原密码。随机生成的 X25519 密钥对中，私钥使用 libsodium `crypto_secretbox_easy` 与 vault 密钥加密后存储；消息使用 libsodium `crypto_box_easy`，把完整消息载荷加密给对端公钥。改密会重新加密同一私钥，保留身份。

云端使用由 Workers Secret `AUTH_PEPPER` 密钥化、带用途分隔的 HMAC-SHA256 校验值，不存储裸密码哈希或可复用的 `authKey`。客户端 vault 密文仍可用于离线猜密码：只拿到数据库的攻击者无法验证 HMAC 而缺少 pepper，但可针对 vault 猜测；同时拿到数据库和 pepper 后，仍可对猜测运行客户端 KDF。云端没有本机额外 scrypt 工作因子。保持 pepper 稳定，替换会使现有登录校验失效。

## 申请、管理员与恢复

成员提交申请后处于待审批状态，批准前不能登录。申请说明由管理员可见且服务端明文保存，不是端到端加密数据。无邀请码。

首次初始化 root 的所有者工具为 `node scripts/manage-root.mjs --local` 或 `node scripts/manage-root.mjs --cloud`；首次密码固定为 `0000`。工具在本机 `data/` 生成随机文件名的私密一次性激活码，首次网页登录必须提供，并立即改密。不要把该文件纳入 Git、备份分享或发布包。root 恢复分别使用 `--local --recover` 或 `--cloud --recover`，会替换 root 身份并撤销旧 root 会话；不得通过清库或重建数据库恢复。

所有者可为成员发放一次性恢复码。使用后账号拥有新身份密钥，旧会话被封存，旧私钥无法恢复，因此旧消息不能解密，联系人必须重新核对安全码。改密码保留身份；忘密恢复不保留身份。安全码只是以双方账号 ID 和公钥计算的 SHA-256 指纹，不是密钥或身份凭据。若对方换身份，必须通过独立可信渠道重新核对。

拒绝或移除账号采用软删除，禁用账号、撤销会话并封存相关会话；保留身份墓碑，已有密文按原期限清理。此操作不是物理擦除承诺；云端数据库历史备份可能保留旧密文。

## 日志与元数据

应用需要来源 IP 做短期速率限制；云端也使用 Cloudflare 边缘限流。账号失败次数的数据库范围键为用户名摘要。root 登录日志记录功能启用后、到达应用的 root 登录尝试时间、IP 与估计位置；不是全站请求日志，不覆盖未到达应用的网络连接失败。当前没有配置该日志的自动保留期限。位置来自网络估算，不代表实际住址。申请说明、账号状态及管理审计记录是服务端可读的元数据。消息正文在客户端加密，但服务端和转发方可能看到 IP、时间、大小、通信关系、会话及消息期限等信息。

Workers 限流按边缘位置工作，不是精确全局防滥用或费用上限。Workers Secrets 中的 `AUTH_PEPPER` 必须保持稳定，不能进入浏览器资源、构建产物或客户端包。会话 Cookie 为随机令牌，D1 只存 SHA-256 摘要，使用 Secure（HTTPS）、HttpOnly、SameSite=Strict 属性。

## 迁移与发布

### 登录设备与 App 持久会话（0.5.3）

`0003_session_devices.sql` 新增独立 `session_devices` 侧表，保存随机公开会话 ID、客户端方式、设备标签与登录来源 IP，并通过外键级联随会话删除。`sessions` 原有列不变，旧代码的显式插入和旧会话继续兼容；旧会话缺少的信息显示未知。只有认证后的账号能列出自己的有效会话，接口不返回 cookie 或令牌摘要。标签可被客户端伪装，不用于授权，也不能证明设备在线。

0.5.3 的网页和 CLI 登录默认为十二小时。明确标为 App 的登录使用极长的服务端期限（截止 9999 年），正常关闭或重启客户端不重新创建会话；Android Keystore 加密保存 cookie 与身份私钥，不保存密码或 authKey。0.5.6 网页 / CLI 新登录可明确申请同一长期路径，条件见后文。显式退出撤销当前会话；改密、成员恢复、账号禁用仍撤销会话。每账号最多八个有效登录，新登录挤出最旧会话。IP 是服务端看到的网络出口，不是设备位置。此活动设备侧表随会话删除；0.5.5 的有限历史另见下节，云厂商备份另有保留边界。

本机服务在自己的数据库中原子应用缺失的迁移；云端由所有者审核后单独应用，再发布新代码。无需更换 `AUTH_PEPPER`、重新生成账号密钥或搬运本机数据。

0.5.4 使用已有侧表，不新增迁移。每次认证读取当前会话的设备元数据，仅在缺少记录或来源 IP 改变时写入：旧会话由对应设备的下一次认证连接自动补齐，已记录会话更新最近连接 IP，不改变登录时间、到期时间、身份或权限。列表中的 IP 因此是最近连接的网络出口；尚未连接的旧设备仍显示等待连接。root 历史登录日志不改写。App 本地恢复先显示无消息的会话界面，服务端验证通过后才开放操作；撤销或身份变化仍清除保存的登录。

### 最近十条登录历史（0.5.5）

`0004_login_history.sql` 新增 `login_history`，记录随机公开 ID、账号关联、设备和方式、最近连接 IP、估计国家 / 地区 / 城市、登录和结束时间及退出 / 过期 / 撤销状态。每账号最多保留最近十次成功登录，按登录时间倒序、同毫秒按插入序号排序；退出后保留，插入新记录时触发器删除超出十条的最旧历史行。此限制不撤销仍有效的会话，也不裁剪 root 原有登录审计。

旧表和凭据不变；迁移补入当时仍有设备信息的会话，无法还原已删除的旧登录。新设备记录插入时由触发器生成历史，删除父会话前记下失效原因；新版本显式退出在同一事务中先标记“退出”。旧 Worker 仍能插入、撤销会话，过渡期间旧版本的主动退出会显示一般“撤销”。接口保留原 `sessions` 数组并新增至多十条 `history`，只给当前认证账号读取，不返回 cookie 或令牌摘要。IP / 地区只按该设备的认证连接更新，未额外调用外部定位服务；不是最初登录位置或在线证明。

发布顺序为审核并单独应用 `0004`，确认旧 Worker 仍可用，再推送依赖新表的代码。涉及显式会话凭据版本列、停用旧直接注册等升级，仍按 `DEPLOYMENT.md` 的分阶段步骤执行。数据库迁移与普通代码推送分开；代码回滚不能重新开放旧直接注册，也不能回滚或重置生产数据库。

### 网页 / CLI 受保护登录与三端入口（0.5.6）

`/api/auth/login` 保留原认证校验，只有网页 / CLI 请求体明确带布尔值 `persistent: true`，且账号不要求首次改密时，才为该次新登录使用既有长期服务端期限和长期 cookie；App 保留原长期路径。缺少标记、字符串 `"true"`、`false` 或需要首次改密的网页 / CLI 登录仍使用十二小时。客户端方式和保留标记不授予新权限，不跳过审批、凭据或会话检查；身份、公钥与密码派生不变。

网页在可用的安全上下文中，通过不可导出的 AES-256-GCM `CryptoKey` 将身份加密保存在 origin 对应的 IndexedDB，密钥对象也由该浏览器存储。cookie 仍由浏览器负责，并保持 HttpOnly、SameSite=Strict 和 HTTPS 下的 Secure；不把 cookie 复制进 IndexedDB 身份记录。不可导出不是硬件隔离或 XSS 保护，同 origin 的恶意脚本仍能使用密钥与登录会话。浏览器保护检测不可用时提示并临时登录；已选择保护保存后写入失败会取消登录，不降级为明文文件。

Windows CLI 通过 DPAPI `CurrentUser` 加密保存 cookie 与身份私钥，按服务 origin 分别存放密文文件；不保存密码、authKey、聊天正文或明文 cookie / 私钥。其他平台或保护检测不可用时提示并临时登录。`/quit` 保留保护文件、清除进程中的解锁状态；`/logout` 清除本机保存并请求远端撤销，断网时不能保证撤销请求到达服务。DPAPI 不防止同 Windows 用户环境中的恶意程序或已控制操作系统。

恢复必须先通过 `/api/account/me` 验证会话、账号与身份，不重新登录、不创建新的登录历史。恢复期间不显示旧的缓存聊天；网络故障保留受保护存储并允许重试，401 / 403、身份变化或首次改密状态则清理并要求重新登录。显式退出、改密、恢复、账号禁用、凭据版本变化及八个有效会话上限的撤销继续生效。浏览器 cookie 策略、站点数据清理或保护存储丢失也可能要求重新登录。

App / 网页“我的”与 CLI `/me`、`/devices`、`/privacy` 分别提供账号、当前设备、服务、版本和隐私信息；改密沿用现有流程及 `/passwd`。设备历史仍复用 `/api/account/sessions` 的 `sessions` 与 `history`，十条历史和八个有效会话分别处理，root 审计不裁剪。0.5.6 不新增数据库迁移、不修改已签发会话的期限，不更换 `AUTH_PEPPER`、不重新生成用户身份、不搬运本机数据。源码实现、测试结果、代码发布和线上验证是不同状态；实际里程碑仅记录在 [DEPLOYMENT.md](DEPLOYMENT.md)。

### Linux CLI（0.6.0）

Linux 使用相同的账号与消息协议。系统 Secret Service 密钥环可用时，每次保存生成独立随机 AES-256 密钥并通过 `secret-tool` 管道存入密钥环；本地只保存绑定服务 origin 的 AES-GCM 登录密文。原密码、authKey、聊天正文和明文 cookie / 私钥不写文件或参数。密钥环不可用时提示临时登录，不申请长期会话；暂时锁定时保留已有密文供解锁后重试。显式退出先删除本地密文，再尽力清理对应密钥并沿用原服务端撤销流程。同一用户环境中的恶意程序仍可能使用系统密钥环，强度取决于密钥环配置。

Linux 登录保护不改变服务端口令派生、已有会话期限和身份。0.6.0 的实时同步另新增下面的元数据迁移。

### 实时连接（0.6.0）

成员经现有 cookie 认证取得 60 秒有效、单次消费的随机连接票据。原始 cookie 不交给 Android WebView；票据只用于 WebSocket 子协议头，不进入 URL、命令行、日志或客户端文件。DO 仅保存票据 SHA-256、原会话哈希及有效期；每个会话最多 4 条待用票据、4 条连接，每个账号最多 16 条连接，既有 8 个有效登录会话上限不变。

握手再次检查会话有效期、凭据版本、账号和成员状态。推送只包含变化提示，不包含会话 ID、密文或图片；每次提示前复核相应会话。账号写入主动复核并关闭失效连接；清理过期会话后也复核。自动心跳仅证明连接可用，不续期登录或授权。即使关闭通知失败，失效会话不能继续获得提示或读取同步数据。

新增 `0005_realtime_journal.sql` 保存有界变更元数据；消息仍留在现有表中。增量接口在同一数据库语句视图中验证身份和参与权限，并应用封存边界。详见 [实时协议](REALTIME.md)。`AUTH_PEPPER`、加密格式和身份不变。
